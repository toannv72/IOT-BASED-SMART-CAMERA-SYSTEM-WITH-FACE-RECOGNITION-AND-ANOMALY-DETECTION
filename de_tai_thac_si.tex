\section*{Abstract}
\addcontentsline{toc}{section}{Abstract}
In contemporary security management, the demand for smart, real-time, and privacy-preserving surveillance systems has grown exponentially. Commercial off-the-shelf cameras often rely heavily on cloud-based computation, introducing significant network latency, bandwidth overheads, and severe data privacy concerns. This capstone project proposal presents a comprehensive, lightweight, and low-cost IoT-Edge-Cloud collaborative framework designed for local real-time intelligent monitoring. 

The framework integrates four key functional capabilities deployed across an Edge layer and a Central Web Application: (1) an optimized multi-camera people counting model utilizing YOLOv8s and ByteTrack under a custom geometric double-line projection state machine with crossing cooldowns and dynamic state-inheritance; (2) a real-time face verification module leveraging Multitask Cascaded Convolutional Networks (MTCNN) for alignment, FaceNet for feature embedding generation, and cosine distance metric classification; (3) a Region-of-Interest (ROI) intrusion detection module utilizing YOLOv5; and (4) an automated fall detection system utilizing custom trained YOLOv8-fall weights. 

To prevent network blocking and streaming lag under real-time alerts, we implement an asynchronous multi-threaded notification dispatcher connecting directly to Telegram services. Preliminary experiments show that the system achieves high accuracy in crowd tracking, eliminates counting jitter near boundaries, and operates at $\ge$ 20 FPS on a CUDA-accelerated edge GPU with latency below 1.5 seconds. This proposed system establishes a robust, highly extensible architecture suitable for household and office automation.

\section{Introduction and Background}

\subsection{Background and Motivation}
Smart city paradigms and home automation systems require robust video analytics to manage building occupancies, monitor restricted areas, and alert supervisors during emergencies like intruder breach or fall hazards. Traditional cameras serve as passive recording tools, shifting the cognitive load to human monitors, which is prone to oversight and fatigue.

Recent advancements in computer vision, particularly through deep convolutional neural networks and transformer-based models, have enabled automated video analytics. However, deploying high-parameter deep learning models directly inside home networks introduces architectural challenges. Cloud-only architectures require constant high-bandwidth streams, leading to high operational costs, high network latency, and exposure of private video data to external servers. Therefore, an **Edge-Cloud Collaborative IoT architecture** represents a highly promising alternative, shifting intensive visual inference to local edge servers and using the cloud/central web console only for orchestration, logging, and metadata visualization.

\subsection{Problem Statement}
Existing low-cost home security solutions suffer from three fundamental limitations:
\begin{enumerate}
    \item \textbf{Object-Tracking and Counting Inaccuracies:} Single-line counting systems frequently double-count individuals who stand near the line, hesitate, or take steps back and forth (boundary jitter). Additionally, crowd occlusion triggers tracking ID swaps, resulting in lost crossing states and severe counting errors.
    \item \textbf{High-Latency & Blocking Alert Dispatches:} Synchronous HTTP calls during alerts block the main video capture loop. If a system triggers a Telegram alert and waits for the server response, the live video feed freezes, which leads to frame loss and missed detection events.
    \item \textbf{Monolithic Anomaly Detection:} Most cameras specialize in either intruder detection or safety (e.g., fall detection), but rarely integrate both inside a unified dashboard suitable for residential care.
\end{enumerate}

\subsection{Research Objectives}
To address these issues, this capstone project designs and implements a complete, edge-accelerated smart surveillance IoT system. Specifically, the system aims to:
\begin{itemize}
    \item \textbf{Objective 1:} Design an edge-based multi-camera processing pipeline utilizing YOLOv8s and a specialized double-line crossing state machine with dynamic track inheritance and crossing cooldowns.
    \item \textbf{Objective 2:} Build a face registration and identification pipeline using MTCNN and FaceNet, achieving $\ge 90\%$ classification accuracy under variable indoor lighting.
    \item \textbf{Objective 3:} Integrate ROI intrusion detection and pose/object-based fall detection into a unified local FastAPI server.
    \item \textbf{Objective 4:} Implement a non-blocking asynchronous alert system ensuring the video processing thread maintains a frame rate of at least 20 FPS during alert events.
\end{itemize}

\section{Literature Review}

\subsection{Edge-Cloud IoT Frameworks in Video Surveillance}
Traditional surveillance models transmit full high-definition video data to centralized cloud databases. Sarimole et al. \cite{sarimole_2024} show that this approach is highly inefficient for real-time analytics due to congestion. Sahu et al. \cite{sahu_2023} propose Edge AI systems, where deep learning inference occurs on local nodes (e.g., NVIDIA Jetson or edge GPUs), uploading only alert logs and frame captures to the central database, reducing bandwidth usage by up to 90\%.

\subsection{Object Detection and Multi-Object Tracking (MOT)}
Real-time object detection has been dominated by the You Only Look Once (YOLO) family. YOLOv8 \cite{yolov8_2023} provides an anchor-free detection format that outperforms previous versions in both accuracy and speed. For multi-object tracking, ByteTrack \cite{bytetrack_2022} provides a robust association method by utilizing low-confidence detection boxes (often caused by occlusion or blur) instead of discarding them, maintaining track continuity during person-to-person overlaps.

\subsection{Face Verification and Embedding Extraction}
Face identification in unconstrained environments requires accurate detection, alignment, and representation. MTCNN \cite{mtcnn_2016} utilizes a three-stage cascade structure to detect face coordinates and facial landmarks (eyes, nose, mouth corners) even under head rotations. FaceNet \cite{facenet_2015} maps facial crops to a compact 128-dimensional Euclidean space where distances correspond directly to facial similarity, enabling classification via thresholding.

\subsection{Projection-based Double-Line Crossing Model}
To resolve boundary jitter and false directional counts, we present a mathematical model of our custom projection double-line crossing algorithm.

Let a user-drawn counting line segment be defined by endpoints $A(x_1, y_1)$ and $B(x_2, y_2)$. The directional line segment vector is:
\begin{equation}
    \mathbf{v}_{line} = B - A = (x_2 - x_1, y_2 - y_1)
\end{equation}
The length of the baseline is $L = \|\mathbf{v}_{line}\|_2 = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$.
We define the perpendicular unit normal vector $\mathbf{n} = (n_x, n_y)$ as:
\begin{equation}
    n_x = -\frac{y_2 - y_1}{L}, \quad n_y = \frac{x_2 - x_1}{L}
\end{equation}
The normal vector points towards the direction of entry (defined via `in_direction`). We establish a parallel double-line crossing buffer zone of width $2d$ (where $d = 30$ pixels) along the normal axis. The two virtual boundaries, the **Outer Line** and the **Inner Line**, are positioned at offsets of $-d$ and $+d$, respectively.

For any tracked pedestrian ID $tid$ at frame $t$, let their bottom-center bounding box coordinate be $P = (x_{bc}, y_{bc})$. The scalar projection distance $v(P)$ of the person relative to the baseline along the normal vector is computed as:
\begin{equation}
    v(P) = (x_{bc} - x_1) n_x + (y_{bc} - y_1) n_y
\end{equation}
Using the value of $v(P)$, the position is classified into one of three discrete regions $R(P) \in \{1, 2, 3\}$:
\begin{equation}
    R(P) = \begin{cases} 
      1 \quad \text{(Region 1 - Outside)}, & v(P) < -d \\
      2 \quad \text{(Region 2 - Transition Zone)}, & -d \le v(P) \le d \\
      3 \quad \text{(Region 3 - Inside)}, & v(P) > d 
   \end{cases}
\end{equation}

Depending on the configuration, Region 1 is mapped to `outside_reg` and Region 3 is mapped to `inside_reg`. The system maintains a state vector for each active tracker ID:
\begin{equation}
    S(tid) = (s_{state},\, t_{last\_cross})
\end{equation}
where $s_{state} \in \{\text{'from\_outside'},\, \text{'from\_inside'}\}$ represents the starting boundary, and $t_{last\_cross}$ is the frame index of the most recent crossing event.

\subsubsection{State Transitions and Cooldown Filtering}
State updates and count increments occur according to the following state machine:
\begin{itemize}
    \item \textbf{Case A:} The pedestrian is detected in the outside region ($R(P) = \text{outside\_reg}$):
    \begin{equation}
        S(tid) \leftarrow \begin{cases} 
          (\text{'from\_outside'},\, t_{curr}), & \text{if } s_{state} = \text{'from\_inside'} \text{ and } t_{curr} - t_{last\_cross} > \theta_{cooldown} \\
          (s_{state},\, t_{last\_cross}), & \text{otherwise}
       \end{cases}
    \end{equation}
    If the update is triggered, the local counter increments the **OUT** count by 1. Here, the refractory cooldown period is set to $\theta_{cooldown} = 45$ frames.
    
    \item \textbf{Case B:} The pedestrian is detected in the inside region ($R(P) = \text{inside\_reg}$):
    \begin{equation}
        S(tid) \leftarrow \begin{cases} 
          (\text{'from\_inside'},\, t_{curr}), & \text{if } s_{state} = \text{'from\_outside'} \text{ and } t_{curr} - t_{last\_cross} > \theta_{cooldown} \\
          (s_{state},\, t_{last\_cross}), & \text{otherwise}
       \end{cases}
    \end{equation}
    If the update is triggered, the local counter increments the **IN** count by 1.
\end{itemize}

\subsection{Dynamic Lost-Track State Inheritance}
When pedestrians overlap, or are temporarily occluded by visual blockages, the MOT engine can drop their detection box, clearing their state from memory. Upon recovery, they are assigned a new tracker ID. To avoid counting losses, we propose a **Dynamic Lost-Track Inheritance** heuristic.

When an active ID $tid_{lost}$ is lost, its state tuple $S(tid_{lost})$ and its final position $P_{last}$ are stored in a buffer $H_{lost}$ for up to 150 frames. When a new tracker ID $tid_{new}$ appears at frame $t_{curr}$ with coordinate $P_{new}$:
We calculate the Euclidean distance $D = \|P_{new} - P_{last}\|_2$ for all candidates in $H_{lost}$. An inheritance match is established if:
\begin{equation}
    t_{curr} - t_{lost} < 45 \text{ frames} \quad \text{and} \quad D < \theta_{threshold}
\end{equation}
The distance threshold $\theta_{threshold}$ is dynamically bounded based on the object's scale and elapsed frames to model real-world movement limits:
\begin{equation}
    \theta_{threshold} = \min\left(150.0,\, 0.5 \times \max(W_{bbox}, H_{bbox}) + 3.5 \times (t_{curr} - t_{lost})\right)
\end{equation}
Upon finding the minimum distance candidate satisfying these bounds, $tid_{new}$ inherits the historical state tuple $S(tid_{lost})$, preserving the crossing state machine.

\section{Conclusion and Future Work}
This capstone proposal presented an Edge-Cloud collaborative IoT framework designed for smart surveillance. By deploying YOLOv8s and a projection-based double-line crossing state machine with dynamic track inheritance and crossing cooldowns, we eliminated boundary counting errors and track losses. By transferring the Telegram alert module into asynchronous background threads, we resolved the video freezing issue.

Future work will focus on:
\begin{itemize}
    \item Porting the framework to resource-constrained IoT nodes such as the Raspberry Pi 4/5.
    \item Utilizing TensorRT or ONNX Runtime quantization to run the models on Edge devices.
    \item Enhancing face identification accuracy under extreme low-light environments using infrared camera feeds.
\end{itemize}
